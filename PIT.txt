================================================================================
           GUIA DE APRESENTAÇÃO DO TCC - SISTEMA DE ANÁLISE FIAT
================================================================================

Este documento serve como base teórica e prática para você apresentar o andamento 
do seu TCC para a banca de professores. Ele explica a arquitetura, as tecnologias, 
a modelagem de dados e fornece um roteiro passo a passo para a sua fala.

--------------------------------------------------------------------------------
1. OBJETIVO DO SISTEMA
--------------------------------------------------------------------------------
O sistema é um assistente de diagnóstico automotivo focado em veículos da marca FIAT.
Ele permite registrar um veículo (com especificações exatas de modelo, ano, motor, 
câmbio e quilometragem) e mapear a jornada de diagnóstico do mecânico/usuário:
- Identificar um SINTOMA (ex: motor falhando em partida a frio).
- Associar o sintoma a possíveis CAUSAS (ex: bateria com baixa carga).
- Apresentar um GUIA DE REPARO passo a passo com tempo estimado e ferramentas.

--------------------------------------------------------------------------------
2. ARQUITETURA GERAL (Como o projeto foi construído)
--------------------------------------------------------------------------------
O projeto adota uma arquitetura MVC Desacoplada (Decoupled MVC) separada em:

A. FRONTEND (View - Apresentação):
   - Desenvolvido em React + Vite.
   - Responsável por renderizar a interface do usuário, capturar as interações
     e enviar dados via requisições HTTP para a API.
   - Estilização robusta e responsiva usando Tailwind CSS.

B. BACKEND (Controller & Model - Lógica e Banco):
   - Desenvolvido em Node.js com Express.
   - Atua como uma API RESTful, recebendo e retornando dados no formato JSON.
   - O Sequelize atua como o ORM (Object-Relational Mapping), traduzindo as 
     entidades JavaScript em tabelas relacionais SQL.

C. BANCO DE DADOS (Persistência):
   - PostgreSQL em produção/desenvolvimento local.
   - SQLite em memória para a execução ágil e limpa de testes de software.

--------------------------------------------------------------------------------
3. MODELAGEM DE DADOS (Entidades e Relações)
--------------------------------------------------------------------------------
Para a banca de TCC, a modelagem relacional é um ponto crítico. Mapeamos quatro 
entidades principais com relações de 1 para Muitos (1:N):

1. VEÍCULO (Vehicle):
   - Representa o veículo cadastrado para diagnóstico.
   - Campos: Modelo, Ano, Motorização, Tipo de Câmbio, Quilometragem.
   - Relação: Um Veículo pode registrar vários Sintomas (1:N).

2. SINTOMA (Symptom):
   - O sinal físico de falha percebido.
   - Campos: Nome do sintoma, Descrição detalhada, Código OBD-II (se houver), Status.
   - Relação: Pertence a um Veículo. Pode ter várias Causas associadas (1:N).

3. CAUSA (Cause):
   - O diagnóstico da raiz do problema.
   - Campos: Nome da causa, Descrição técnica, Probabilidade (Alta/Média/Baixa).
   - Relação: Pertence a um Sintoma. Pode requerer vários Guias de Reparo (1:N).

4. GUIA DE REPARO (RepairGuide):
   - O procedimento prático para solucionar o problema.
   - Campos: Título, Descrição, Passos (instruções), Tempo Estimado, Dificuldade, Ferramentas.
   - Relação: Pertence a uma Causa.

--------------------------------------------------------------------------------
4. ENGENHARIA E QUALIDADE DE SOFTWARE (O diferencial do seu TCC)
--------------------------------------------------------------------------------
Bancas acadêmicas valorizam testes automatizados. O projeto conta com:

- Testes Unitários: Validam individualmente as propriedades de cada tabela
  (se os campos existem e estão no formato correto) e as associações entre modelos.
- Testes de Integração: Simulam um fluxo real completo no banco de dados. 
  Eles criam um Veículo -> Sintoma -> Causa -> Guia de Reparo e consultam a árvore 
  completa por meio de Joins aninhados (`Sequelize includes`), verificando a 
  integridade referencial de ponta a ponta.

--------------------------------------------------------------------------------
5. ROTEIRO DE APRESENTAÇÃO (O que falar para os professores)
--------------------------------------------------------------------------------

[PASSO 1: A Introdução e o Problema]
"Olá, professores. O objetivo do meu TCC é simplificar e estruturar o processo de
diagnóstico mecânico, especificamente focado na linha de veículos FIAT. O sistema 
guia o usuário desde o preenchimento dos detalhes do carro até a solução do problema."

[PASSO 2: A Experiência do Usuário (Frontend)]
"No Frontend, utilizamos React e Tailwind CSS para criar uma interface moderna e 
intuitiva. Quando o usuário escolhe um Modelo, o sistema busca na API e filtra 
automaticamente os anos disponíveis para aquele modelo, depois os motores e os 
câmbios compatíveis. Isso evita erros de preenchimento e melhora a experiência."

[PASSO 3: A Arquitetura do Sistema e o Banco de Dados]
"O backend é uma API em Node.js com Express e Sequelize ORM conectado ao PostgreSQL.
Para esta etapa, focamos na modelagem relacional de diagnóstico, criando 4 entidades 
fortemente relacionadas: Veículo, Sintoma, Causa e Guia de Reparo. Toda a integridade 
de chaves estrangeiras e a cascata de exclusões foram configuradas no banco de dados."

[PASSO 4: Demonstração de Qualidade e Testes]
"Para garantir a robustez da aplicação, implementamos testes unitários e de integração 
automatizados utilizando Jest. Em ambiente de testes, rodamos um banco SQLite em 
memória para isolar e acelerar a validação. Conseguimos testar com sucesso toda a 
cadeia de relações, desde a inserção do carro até a busca do guia de reparo aninhado."

[PASSO 5: Próximos Passos e Conclusão]
"Com a base de dados mapeada e validada, os próximos passos do projeto consistem 
em integrar as telas de diagnóstico no frontend para exibir dinamicamente essas 
causas e guias de reparo conforme o carro selecionado pelo usuário. Obrigado."

--------------------------------------------------------------------------------
6. DETALHAMENTO DAS FERRAMENTAS E TECNOLOGIAS UTILIZADAS
--------------------------------------------------------------------------------

Abaixo está a justificativa técnica de cada ferramenta usada no projeto, para 
caso os professores perguntem o "porquê" de cada escolha:

A. FRONTEND:
   - REACT.JS: 
     Biblioteca JavaScript para construção de interfaces baseadas em Componentes. 
     Permite que o estado da aplicação (como os dados do carro e do formulário) 
     seja reativo. Quando o estado muda, a tela se atualiza automaticamente.
   - VITE:
     Ferramenta moderna de build (empacotador) que substitui o antigo Create React App. 
     Utiliza módulos ES nativos no navegador para oferecer carregamento instantâneo 
     durante o desenvolvimento (Hot Module Replacement - HMR) e builds rápidos de 
     produção usando Rollup.
   - TAILWIND CSS:
     Framework CSS utilitário ("utility-first"). Em vez de escrever arquivos CSS 
     separados com classes customizadas (como .botao-vermelho), você aplica classes 
     utilitárias diretamente no HTML/JSX (ex: `className="bg-red-600 text-white p-4 
     rounded-xl"`).
     * Vantagens para o TCC:
       - Produtividade altíssima no desenvolvimento de layouts responsivos.
       - Consistência de design (usa uma escala padrão de espaçamento, cores e fontes).
       - Desempenho otimizado, pois o compilador do Tailwind gera apenas o CSS 
         que foi realmente utilizado no código ("purging").
   - LUCIDE REACT:
     Conjunto de ícones vetoriais modernos e leves, integrados perfeitamente com 
     o React (como ícones de carros, alertas e sucesso).

B. BACKEND & BANCO DE DADOS:
   - NODE.JS:
     Ambiente de execução Javascript server-side. Permite usar a mesma linguagem 
     (JavaScript) no frontend e no backend, unificando a stack do projeto.
   - EXPRESS.JS:
     Framework Web minimalista para Node.js. Facilita a criação de rotas HTTP 
     (GET, POST, etc.) e o tratamento de requisições de forma limpa e estruturada.
   - SEQUELIZE (ORM):
     Mapeador Objeto-Relacional (ORM) para bancos relacionais. Traduz as tabelas do 
     banco de dados em classes e objetos JavaScript. Isso significa que podemos 
     criar registros, fazer relações e buscar dados complexos usando métodos JS 
     (como `Vehicle.findAll()`) sem precisar escrever queries SQL cruas manualmente.
   - POSTGRESQL:
     Banco de dados relacional robusto, de código aberto, com alta confiabilidade 
     e performance, perfeito para aplicações reais.
   - CORS (Cross-Origin Resource Sharing):
     Middleware de segurança essencial que permite que o frontend (rodando em 
     http://localhost:5173) consiga fazer requisições seguras para a API backend 
     (rodando em http://localhost:3000).

C. QUALIDADE E DESENVOLVIMENTO:
   - JEST:
     Framework de testes unitários e de integração JavaScript mais popular do mercado, 
     utilizado para garantir que alterações futuras não quebrem as regras de negócio.
   - SUPERTEST:
     Biblioteca usada nos testes de integração para simular chamadas HTTP nas rotas 
     do Express de forma programática, sem precisar subir a API na rede de verdade.
   - SQLITE3:
     Banco de dados relacional leve em arquivo. Configurado para rodar "em memória" 
     durante a suíte de testes do Jest, permitindo testes rápidos e que se auto-destroem, 
     sem alterar o banco PostgreSQL principal de desenvolvimento.
   - DOTENV:
     Gerenciador de variáveis de ambiente. Armazena credenciais confidenciais 
     (como a senha do banco de dados) de forma isolada em um arquivo `.env` que 
     não vai para o controle de versão.
